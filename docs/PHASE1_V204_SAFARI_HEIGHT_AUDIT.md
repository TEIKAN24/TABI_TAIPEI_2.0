# TAIPEI CITY GUIDE 2.0 — v2.0.4｜iPhone Safari 頂部與版面高度修正

**視覺來源：** Figma `TABI-TAIPEI`，首頁 `Title (1:408)`、`side (67:1170)`、旅支度 `56:278 / 1:146 / 1:197`；使用者提供的參考圖 `Title.png`（393×852）及 iPhone Safari 截圖 `IMG_4459.PNG`（944×2048，已縮圖）。**未修改 Figma。**

## 問題與處置

1. **iPhone Safari 網站偏低：** 在使用者的瀏覽器截圖中，Logo 與章節間有接近一個 iOS 狀態列高度（約 **58 CSS px**）的額外頂部空間；之前的 CSS 在站台內仍保留整個 `104px` 的 Figma 頂部空間。對 Safari **瀏覽器分頁**使用 `46px` 的頂部欄（104−58）；因此在真機頂部系統安全區造成的偏移之後，Logo 仍回到 Figma 的約 `Y=78px`。側邊選單與遮罩也做對應的 -58px 相對調整，確保章節與斜線不受影響。
2. **其他環境不受牽連：** 只對 `iPhone/iPod + Safari + 非 standalone` 新增 `tt-ios-safari-tab` 標記，Chrome/Android、桌面，以及透過「加入主畫面」開啟的 Web App 均維持原本 `104px` Figma 基準。這是依實機截圖校正的針對性修正，並非假定所有 iOS 版本安全區相同。
3. **不要底部版權文字：** 將 `body > footer.wrapper` 在 2.0 介面中隱藏（`display:none`），HTML 原文、相關資料均未刪除。
4. **高度：** 使用 `svh` 作為基準、瀏覽器支援時用 `dvh` 適應動態工具列，首頁不再因頁尾造成額外捲動；只有首頁套用，章節頁保留正常捲動功能。
5. **旅支度：** 依原來的 Figma 設計保留 34px 章節標題、46px 切換欄、七項 42px 間隔與底部線條。修正向右箭頭的 CSS 描繪，使其有清楚的箭柄、尖端及 18px 中心旋轉；文字仍是 HTML，沒有製作圖片按鈕。

## 互動與相容性驗證

本機將 HTML/CSS/JS 和原 SVG 字形以原生元素載入 Chromium，模擬 320、393、430、440px 寬；也分別模擬 Safari Tab UA 與 iOS standalone：

- 393 桌面／iOS standalone：站台標題欄 104px，Logo DOM `y=78`；Safari Tab 模擬：站台標題欄 46px，Logo DOM `y=20`（預期在 iOS 系統上方約 58px 安全區之後，實際螢幕位置為 y≈78）。
- 320、393、430、440px 模擬：首頁沒有原本的頁尾文字、首頁無多餘的縱向捲動；沒有 JavaScript 例外。
- 旅支度三個分頁（注意事項／入国カード／交通パス）正常；七項收合可操作；僅允許同時一項展開。
- 側邊選單可展開，點選「観光」導向 sights，再點 Logo 返回首頁。
- 資料庫 `data/` **8/8**、`food/` **7/7** 相對 v2.0.3 **位元內容完全相同**；其他原本 JS 和 SVG 字形未修改。
- Service Worker 快取版本提升至 v2.0.4，加入新樣式檔預先快取。

**尚未驗證：** 使用者實際 iPhone／Safari 版本在瀏覽器網址列展開、收起時，和加入主畫面後的真實安全區；亦未重新實機驗證地圖、イベント及路線動畫。上述程式與資料本版均未改動。舊 Safari 版本與非動態島裝置可能有不同的安全區高度，部署後應以真機截圖再量測。
